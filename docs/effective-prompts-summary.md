# Backpack API 开发过程中的有效提示词总结

## 项目背景
用户要求实现一个使用 JavaScript 的 Backpack 自动化脚本，可以查询账户余额和订单，查询代币价格，查询市场买1卖1订单，并进行合约下单。

## 提示词有效性特征分析

### 高效提示词的共同特点

1. **具体性强**
   - 明确指定技术栈、API、交易类型
   - 提供具体的参数和示例
   - 指出具体的错误和问题

2. **上下文完整**
   - 提供相关的参考文档
   - 说明配置和环境要求
   - 解释业务逻辑和约束条件

3. **渐进式指导**
   - 按步骤分解复杂任务
   - 先总结再实现的方法论
   - 及时纠正和优化方向

4. **实际问题导向**
   - 基于真实的技术问题
   - 考虑实际的交易场景
   - 提供可行的解决方案

5. **机器人开发特有特点**
   - 明确区分概念（如成交订单 vs pending订单）
   - 强调实时API数据 vs 本地计算
   - 指出业务逻辑错误（如订单方向、持仓判断）
   - 要求配置管理最佳实践

### 提示词改进建议

1. **更早提供完整需求**
   - 在项目开始时就明确所有技术约束
   - 提前说明配置和环境要求
   - 明确测试和验证标准

2. **提供更多技术细节**
   - 具体的API端点和参数格式
   - 错误处理和边界情况
   - 性能和安全要求

3. **增加验证步骤**
   - 每个功能的测试方法
   - 预期的输出和结果
   - 错误情况的处理方式

## 经验总结

1. **明确需求是关键**: 清晰的需求描述能够避免大量的返工和修正
2. **渐进式开发有效**: 先总结文档，再逐步实现的方法提高了开发效率
3. **及时纠正很重要**: 在发现问题时立即指出并提供解决方案
4. **实际测试验证**: 基于真实场景的测试能够发现潜在问题
5. **文档化价值**: 将开发过程和经验文档化有助于后续维护和改进

**原始提示词**:
> "止盈目标 PROFIT_TARGET 改成 除手续费之外的止盈对应比例，比如MAKER_FEE=0.0001，买卖一次就是 0.02%，除手续费之外的止盈对应比例如果是 0.0001,那要上涨0.03%"

**有效性分析**:
- ✅ 明确了新的需求（百分比止盈而非绝对金额）
- ✅ 提供了具体的计算逻辑和示例
- ✅ 考虑了手续费成本的自动计算
- ✅ 给出了具体的数值示例

**实现效果**: 
- 总盈利比例 = 净盈利比例 + 手续费比例
- 自动考虑开仓和平仓的手续费成本
- 更精确的盈利控制机制
