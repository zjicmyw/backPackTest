## V1.4 - 限价刷交易量模式 (2025-10-09)

### 🎯 设计目标

新增一种专门用于刷交易量的限价模式bot，通过低手续费限价单大量刷交易量，同时保持始终在1档位的策略。

### 📋 核心特性

#### 1. 纯限价交易
- **禁止市价单**: 所有交易只能通过限价单完成
- **低手续费**: 利用限价单的maker手续费优势
- **高频交易**: 通过快速成交实现大量交易量

#### 2. 智能持仓管理
- **无持仓状态**: 同时维护买1和卖1两个限价单
- **有持仓状态**: 只维护一个平仓限价单
- **自动切换**: 持仓状态变化时自动调整订单策略

#### 3. 实时价格跟踪
- **WebSocket监控**: 实时监控1档位价格变化
- **自动调整**: 价格变化时自动调整订单到1档位
- **快速响应**: 确保订单始终在最优价格

### 🔧 技术架构

#### 状态管理
```javascript
class LimitVolumeBot {
    constructor(config) {
        // 持仓状态
        this.hasPosition = false;
        this.positionSide = null; // 'long' | 'short'
        this.positionQuantity = 0;
        
        // 订单管理
        this.activeOrders = new Map(); // orderId -> orderInfo
        this.buyOrderId = null;
        this.sellOrderId = null;
        this.closeOrderId = null;
        
        // 价格监控
        this.priceCheckTimer = null;
        this.lastBestPrices = null;
    }
}
```

#### 核心算法流程
```javascript
// 1. 无持仓状态：维护买1和卖1订单
async maintainNoPositionOrders() {
    const bestPrices = await this.client.getBestPrices(this.config.symbol);
    
    // 确保有买1订单
    if (!this.buyOrderId) {
        this.buyOrderId = await this.placeLimitOrder('buy', bestPrices.bestBid[0]);
    }
    
    // 确保有卖1订单
    if (!this.sellOrderId) {
        this.sellOrderId = await this.placeLimitOrder('sell', bestPrices.bestAsk[0]);
    }
}

// 2. 有持仓状态：维护平仓订单
async maintainPositionCloseOrder() {
    const bestPrices = await this.client.getBestPrices(this.config.symbol);
    const closePrice = this.positionSide === 'long' 
        ? bestPrices.bestBid[0]  // 多头平仓用买1
        : bestPrices.bestAsk[0]; // 空头平仓用卖1
    
    if (!this.closeOrderId) {
        this.closeOrderId = await this.placeCloseOrder(closePrice);
    }
}
```

### 🐛 问题修复记录

#### 订单状态追踪问题 (2025-10-09)
- **问题描述**: 限价订单创建成功后立即尝试调整价格，但订单可能已成交导致404错误
- **根本原因**: 缺少订单状态检查，没有区分等待成交和已成交的订单
- **修复方案**: 
  - 在调整订单价格前先检查订单状态
  - 只有 `New` 或 `PartiallyFilled` 状态的订单才调整价格
  - `Filled` 状态的订单直接处理成交逻辑
  - `Cancelled` 状态的订单清除订单ID
  - 404错误时查询历史订单确认状态

#### 订单数量限制问题 (2025-10-09)
- **问题描述**: 机器人频繁创建和取消订单，没有正确检查持仓状态
- **根本原因**: 缺少持仓状态检查，没有限制同时存在的订单数量
- **修复方案**:
  - 同时最多只能存在一个限价买单和一个限价卖单
  - 如果持仓数量 >= `VOLUME_ORDER_QUANTITY`，不允许开仓
  - 如果持仓数量 < `VOLUME_ORDER_QUANTITY`，不允许平仓
  - 订单替换时重新检查持仓状态
  - 确保订单数量与持仓状态匹配

#### 持仓方向限制问题 (2025-10-09)
- **问题描述**: 持仓方向检查不够精确，没有区分多头和空头持仓的限制
- **根本原因**: 只检查持仓数量的绝对值，没有考虑持仓方向
- **修复方案**:
  - 多头持仓 >= `VOLUME_ORDER_QUANTITY`：禁止买单（开多），只允许卖单（平多）
  - 空头持仓 <= `-VOLUME_ORDER_QUANTITY`：禁止卖单（开空），只允许买单（平空）
  - 新增 `adjustBuyOrderOnly()` 和 `adjustSellOrderOnly()` 方法
  - 平仓订单根据持仓方向选择正确的订单类型
  - 精确的持仓方向检查，避免错误的方向操作

#### 订单替换逻辑问题 (2025-10-09)
- **问题描述**: 日志记录的是替换订单，但实际情况是下了新的订单，老的订单还在
- **根本原因**: `replaceOrder`方法中，当`oldOrderId`为`null`时，仍然尝试取消订单
- **修复方案**:
  - 在`replaceOrder`方法中添加`oldOrderId`检查
  - 只有当`oldOrderId`存在时才尝试取消订单
  - 避免传递`null`或`undefined`给`cancelOrder`方法
  - 改进订单创建逻辑，添加详细的日志记录
  - 优化订单状态管理，确保订单ID的正确传递
  - 避免重复创建订单，提高系统稳定性

#### 订单积累Bug修复 (2025-10-09)
- **问题描述**: 替换或取消订单的代码逻辑有bug，会积累很多订单
- **根本原因**: 
  - `activeOrders`映射更新不完整，新订单没有添加到映射中
  - 订单替换失败时没有正确清理状态
  - 缺少订单创建前的重复检查
  - 缺少过期订单记录清理机制
- **修复方案**:
  - 修复`replaceOrder`方法中的`activeOrders`映射更新
  - 添加新订单到`activeOrders`映射，确保状态跟踪完整性
  - 在订单替换失败时清理`buyOrderId`、`sellOrderId`、`closeOrderId`
  - 添加订单创建前的重复检查，防止创建相同价格的订单
  - 新增`cleanupExpiredOrders()`方法，定期清理过期订单记录
  - 改进错误处理和日志记录，添加`activeOrdersCount`到日志输出
  - 在价格检查循环中定期清理过期订单（每10次价格检查）

#### 订单撤销逻辑增强 (2025-10-09)
- **问题描述**: 替换订单时需要确保正确撤销原订单
- **改进方案**:
  - 增强撤销确认机制，撤销后验证订单状态
  - 完善错误处理，区分不同类型的撤销错误
  - 立即清理活跃订单映射，确保状态同步
  - 添加等待机制，给交易所足够时间处理撤销请求
  - 提供详细的撤销日志记录
  - 处理 "Order not found" 和 "Order already cancelled" 错误
  - 确保撤销成功后立即从映射中移除旧订单

#### 订单替换频率优化 (2025-10-09)
- **问题描述**: 订单替换频率过高，1秒一次过于频繁
- **修复方案**:
  - 将价格检查间隔从1秒调整为5秒
  - 更新默认配置：`VOLUME_PRICE_CHECK_INTERVAL=5000`
  - 避免过于频繁的订单操作，减少API调用压力
  - 提供更稳定的交易体验

#### 最大持仓金额限制功能 (2025-10-09)
- **功能描述**: 新增最大持仓金额限制，超过限制时禁止同方向开仓
- **实现方案**:
  - 新增`VOLUME_MAX_POSITION_VALUE`环境变量配置
  - 新增`calculatePositionValue()`方法计算持仓金额
  - 新增`checkPositionValueLimit()`方法检查持仓金额限制
  - 在订单创建前检查持仓金额和方向
  - 同方向订单被禁止，反方向订单被允许（平仓）
  - 提供详细的日志记录和调试信息

#### 持仓金额限制Bug修复 (2025-10-09)
- **问题描述**: 持仓金额超过限制时，仍然创建同方向的订单
- **根本原因**: 
  - 持仓金额检查只在方法开头做了一次
  - 在订单创建逻辑中，没有再次检查持仓金额限制
  - 只检查了持仓方向限制（基于数量），没有检查金额限制
  - 持仓金额检查逻辑分散，不够统一
- **修复方案**:
  - 统一持仓金额检查逻辑，在方法开头进行
  - 持仓金额限制优先于持仓方向限制
  - 超过限制时立即返回，不继续执行后续逻辑
  - 取消现有同方向订单，只允许反方向订单
  - 移除分散的重复检查，确保逻辑一致性
  - 提供详细的限制检查日志

#### 严格持仓方向限制 (2025-10-09)
- **问题描述**: 需要确保持有多头持仓时不新建买入订单，持有空头持仓时不新建卖出订单
- **实现方案**:
  - 严格基于持仓方向限制同方向开仓
  - 多头持仓 (netQuantity > 0)：禁止买单，只允许卖单（平多）
  - 空头持仓 (netQuantity < 0)：禁止卖单，只允许买单（平空）
  - 自动取消现有的同方向订单
  - 提供详细的限制日志记录
  - 简化逻辑，不依赖持仓数量阈值

## V1.2.1 - 订单查询404错误修复 (2025-10-09)

#### 市价订单查询404错误
- **问题描述**: 市价订单创建成功并成交后，查询订单状态时返回404错误
- **根本原因**: `/api/v1/order` 端点只能查询未成交订单，已成交订单无法通过此端点查询
- **影响范围**: 速刷合约交易机器人的市价关仓订单状态检查

### 🔧 修复内容

#### 1. 优化订单状态检查逻辑
```javascript
// 修改前：总是查询订单状态
const order = await this.client.getOrder(marketOrderId, this.config.symbol);

// 修改后：检查初始状态，避免不必要的查询
if (initialStatus === 'Filled') {
    this.handleMarketOrderFilled(marketOrderId, limitOrder);
    return;
}
```

#### 2. 增强404错误处理
```javascript
// 新增404错误处理逻辑

    return;
}
```
